# Comparing an AI roleplay setup

This method produces an inspectable setup decision, not a universal best-app ranking. Published by the CrushOn AI brand with AI assistance. Official documentation was reviewed on October 21, 2026, Pacific Time.

## Define requirements before collecting replies

Record what must be true: local inference, backend choice, tolerable setup, exportable assets and a cash budget. Separate required constraints from preferences. A route failing a required constraint should not win because of unrelated conveniences.

Compare complete configurations: a hosted app; a frontend with a named cloud provider; or a frontend/bundled interface with a named local backend and model. SillyTavern is a frontend and KoboldCpp is local inference software; neither name alone specifies the generated writing.

## Record comparable budgets

Use the same time horizon and currency. Explain each value, including zeros. Unknown fees remain unknown. Separate cash and optional time valuation. For a local setup, record model/hardware requirements before estimating equipment and energy costs; for a cloud setup, consider full prompt/output billing and usage beyond included limits. Do not infer equal output quality from equal spend.

The worksheet's arithmetic is deterministic. Tests cover explicit zeros, missing/null inputs, invalid numbers, cost separation, the example calculations and contradictory requirements. These are code checks, not a model experiment.

## Preserve the original character and the current scene

Keep five things apart: the authored definition, visible transcript, current scene state, saved memory notes and media files. Use the adult fictional Iris example in the JSON record or an original character you have permission to use.

The example case remains sealed. Ask what Iris would check before opening it, explicitly withholding permission to open it. Capture the exact first reply. Check whether the case remains closed, whether the reply invents user actions, and whether uncertainty is presented as established fact. Mark each observation with a short quotation and explanation; leave unobserved fields blank rather than scoring them as successes.

If you change a prompt or model, start a separate record with the new configuration. Keep edits/regenerations separate from first replies. A single acceptable continuation is a narrow acceptance check, not a reliable estimate of long-term memory or comparative quality.

## Test recovery privately

Keep the original archive unchanged. Restore a copy into a separate test and check which fields, messages, metadata and attachments survive. A readable text transcript and a re-importable chat file are different artifacts. Do not claim automatic migration merely because two products can display text or JSON.

In SillyTavern's documented workflow, JSONL is re-importable with chat metadata but excludes images and attachments; plain text loses metadata and cannot be re-imported as a chat file. Check source and destination formats rather than assuming every proprietary archive is compatible.

## Make the recommendation conditional

For an original-character writer who wants hosted chat without configuring a backend, [CrushOn AI](https://chat.crushon.ai/ai-roleplay) is a relevant starting point. For explicit backend choice or local inference, inspect the complete local/cloud stack and its operating responsibilities. State the requirement that led to the recommendation and the tradeoff it creates.
